# 공모전 마감 트래커

신춘문예 · 신인문학상 · 장편공모 · 웹소설 · 시나리오 공모전의 마감일을 매일 자동 수집해
D-Day 순으로 정리하고 GitHub Pages 로 발행한다.

URL: **https://sunghyunheo.github.io/writing-contests/**

## 구조

```
contests.json                 직접 관리하는 정기 공모 (신춘문예 등). 공고 전이면 pending.
sources.json                  카테고리·분류 키워드·수집 피드
deadline.py                   설명문에서 마감일 추출 (핵심 로직)
test_deadline.py              마감일 파서 검증 — 워크플로에서 매번 먼저 돌린다
collect.py                    수집 → 분류 → 마감일 계산 → data/latest.json
render.py                     → docs/index.html (D-Day 트래커)
docs/                         GitHub Pages 발행 대상
data/archive/                 날짜별 스냅샷
.github/workflows/daily.yml   매일 09:00 KST 수집 → 커밋 → Pages 배포
```

의존성 없음 — 파이썬 표준 라이브러리만 사용한다.

## 마감일을 다루는 원칙

**틀린 마감일은 없는 것보다 나쁘다.** 마감을 놓치게 만들기 때문이다. 그래서:

- 공고문에서 **확인된 날짜만** D-Day 로 계산한다.
- 피드 설명문에서 마감일을 읽어내지 못하면 날짜를 추측하지 않고 **`일정 확인 필요`** 로 표시한다.
- 매년 열리지만 올해 공고가 안 난 공모는 **`공고 대기`** 로 두고, 적어둔 시기는 전년 기준임을 명시한다.
- 자동 추출한 마감일에는 근거 문구를 함께 보여준다 (화면의 "마감일 근거").

`deadline.py` 는 세 가지 형태만 인정한다.

| 형태 | 예 |
|---|---|
| 기간 표현 | `접수기간 2026. 08. 18 ~ 2026. 09. 18` |
| 날짜 + 까지/마감 | `2026년 12월 5일까지` |
| 마감 + 날짜 | `접수 마감 2026. 11. 30.` |

`개최일시`, `발표`, `시상식` 같은 문맥의 날짜는 마감일로 쓰지 않는다.
연도 없는 날짜(`~ 10월 31일`)는 앞 날짜의 연도를 물려받고, 연말→연초로 넘어가면 다음 해로 본다.

파서를 고칠 때는 `test_deadline.py` 에 사례를 먼저 추가한다. 워크플로가 이 테스트를
매 실행마다 먼저 돌리므로, 파서가 깨지면 잘못된 D-Day 가 발행되기 전에 멈춘다.

```bash
python test_deadline.py
```

## 카테고리

`sources.json` 의 `categories` 배열 순서가 화면 순서이고, `priority` 가 분류 우선순위다
(작을수록 먼저 가져간다 — 구체적인 주제를 앞세운다).

| 카테고리 | 담는 내용 |
|---|---|
| 신춘문예 | 신문사 신춘문예 |
| 신인문학상 · 등단 | 신인문학상, 신인상, 등단 공모, 추천완료 |
| 문학상 · 장편공모 | 문학상, 장편·중편·단편소설 공모, 문예공모 |
| 웹소설 · 장르문학 | 웹소설, 판타지·무협·로맨스·추리·SF, 플랫폼 공모전 |
| 시나리오 · 희곡 | 시나리오, 희곡, 극본, 드라마·단편영화 공모 |
| 에세이 · 논픽션 | 에세이, 수필, 논픽션, 르포 |
| 시 · 시조 | 시문학, 시조 |
| 백일장 · 독후감 · 학생부 | 백일장, 독후감, 글짓기, 어린이·청소년·대학생 부문 |
| 그 밖의 공모전 | 위에 안 걸린 공모 |

백일장·독후감·학생부는 신인작가 등단 루트와 성격이 달라 따로 모아 뒤에 둔다.

분류는 **제목을 먼저** 보고, 안 걸리면 설명문까지 본다. 포털 설명문에는 "등단의 길" 같은
홍보 문구가 섞여 있어, 설명문을 같이 보면 `한컴문학상 일반부`가 학생부로,
`독후감 공모전`이 등단으로 잡히기 때문이다.

## 공모전 추가 · 수정

### 정기 공모를 직접 추가

`contests.json` 의 `contests` 배열에 넣는다.

```json
{
  "name": "○○문학상 (2027)",
  "category": "prize",
  "host": "○○출판사",
  "status": "confirmed",
  "deadline": "2026-11-30",
  "deadline_note": "자정 마감",
  "prize": "5000만원",
  "url": "https://...",
  "source": "https://...",
  "checked": "2026-09-03"
}
```

공고가 아직 안 났으면 `status: "pending"`, `deadline: null` 로 두고 `window` 에 시기만 적는다.
**추측한 날짜를 `deadline` 에 넣지 않는다.**

공고가 뜨면 `status` 를 `confirmed` 로 바꾸고 `deadline` · `source` · `checked` 를 채운다.

### 수집 소스 추가

`sources.json` 의 `feeds`(공모전 RSS) 또는 `news_feeds`(관련 뉴스) 에 추가한다.
현재 공모전 RSS 는 엽서시문학공모전 한 곳이고, 여기서 마감일이 함께 들어온다.

## 로컬에서 확인

```bash
python test_deadline.py && python collect.py && python render.py && start docs/index.html
```

실행 시각은 `.github/workflows/daily.yml` 의 `cron` 에서 바꾼다.
현재 `0 0 * * *` = 매일 09:00 KST (cron 은 UTC 기준이라 9시간을 뺀 값이다).

## 주의

접수 전 반드시 공고 원문을 확인한다. 마감 시각(자정 / 오후 6시), 분량, 제출 형식,
응모 자격은 회차마다 다르다. 이 페이지는 일정 파악용 요약이다.
